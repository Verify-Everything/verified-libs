# Lean proofs over Aeneas output

Project layout (made by `vkit new --lang rust`): `libraries/<lib>/<Module>/`
- `Extracted/` generated by Aeneas each run. Never edit.
- `External/FunsExternal.lean` your models of std functions Aeneas could not translate.
- `Spec.lean` an independent reference spec. `Proofs.lean` (or several files) the theorems.

Loop: edit, then `vkit run <lib>` (fetch, extract, build, audit) or `lake build` inside the
project for a faster inner loop. Build only after real edits; mathlib is large.

## Trust rules (the engine audits these)
- Only propext, Classical.choice and Quot.sound may appear in `#print axioms` of a claimed theorem.
- Forbidden (CI fails the entry): `sorry`, `admit`, new `axiom`, `native_decide`, `bv_decide`,
  `implemented_by`, `@[extern]`, `unsafe`, `opaque` in specs, options that skip kernel checks.
  Proofs are also replayed by `lean4checker`.
- Every `def` in FunsExternal.lean that models std is a trusted assumption: list it in CLAIM.md's
  Trusted base with a differential test against real std, or prove it against a reference.
- Proofs must be about the extracted upstream code. A model crate needs a model-to-code proof.

## Every function needs a theorem
The engine marks a function verified only when a proved theorem specifies it (found
automatically by name, or mapped in `libraries/<lib>/functions.toml`). A library is finished
at Functions N/N, so plan one step theorem per extracted function, helpers included. Functions
Aeneas skipped stay open: a tool-friendly patch proved equivalent to the original, a model
with a model-to-code proof, or a second tool.

## Spec style that worked
1. Pure reference spec on simple types (`List Nat`, `BitVec 32`) as ordinary recursive functions.
2. Lemmas on the spec alone (round trip, linearity, concatenation).
3. One step theorem per Rust function relating it to the spec:
   `theorem f_spec ... : f x ⦃ r => r.val = spec x.val ⦄` tagged `@[step]` (or `@[progress]`)
   so later proofs reuse it.

## Tactics
- `unfold f; step*` (or `progress*`) walks monadic code. Finish with `subst_vars`, `simp_all`,
  `scalar_tac`, `omega`, `split at h`, `getElem!_pos l i h` (turns `l[i]!` into `l[i]`).
- Binds: generated code uses both `Std.bind` and `Bind.bind`; `rfl` won't reduce them. A macro
  `first | rw [bind_ok] | rw [bind_tc_ok]` steps one bind.
- Loops become `_loop` defs: write an unfold lemma, then prove by induction on the decreasing
  measure with separate lemmas for the body and the exit.
- Iterators: prove a spec for one `next` call ("chunk ++ spec rest = spec input", length
  decreases), then a fuel-bounded `collect` equals the spec by induction on fuel.
- Finite facts and tables: `decide +kernel` over `∀ n < 256, ...` (768-byte table ~10 s;
  4,096 entries ~6 s). Stays kernel-checked.
- Bit-vectors without bv_decide: prove linearity once by cases on low bits; bit-by-bit
  identities via `BitVec.eq_of_getLsbD_eq` and `iterate 32 (rcases i with _ | i; · simp ...)`;
  `bv_omega` for bounds. Use `getLsbD`, not `x[i]`. GF(2)-linear maps: compare on 32 basis
  vectors with `decide +kernel`.
- Orientation: write postconditions as `spec x = r.map (·.val)` (spec on the left) so
  `simp_all` doesn't rewrite `none` into the spec and get stuck.
- Literals like `16#usize` carry proofs that break `simp` ("motive is not type correct"):
  state helpers over `Usize.ofNat n hn` and use `rw`/`show`.

More patterns and known library gaps: [references/aeneas-gaps.md](references/aeneas-gaps.md),
and the latest lessons in `notes/general.md`.
